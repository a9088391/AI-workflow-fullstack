# 驗證紀錄與範圍

本專案以本機展示為驗收目標。以下結果來自專用的 Docker Compose 環境與合成資料。驗收分為框架測試、HTTP／PostgreSQL 契約、瀏覽器操作及查詢效能。

## Rails05 增量驗證狀態

第 05 票的本機整合與真 UI 驗證範圍如下；本段不代替 L3 四路 Review、development acceptance 或 Git／部署授權。可重現入口及隔離前提見[開發指南](developer-guide.md#rails05-十三後端-http-回歸)，啟停與回復步驟見[維運指南](database-operations.md)。

首輪原十二版 132 組與 Rails 前兩組通過後，因驗證工具的 trace 路徑斷言失敗而停止；原始失敗保留。修正後 Rails 11 組定向複驗通過，最後再完成十三版 143 組。原十二版各完成兩輪完整案例；完整十三版整輪結果為最後一輪。

Linux ARM64 同時有 19 個應用及 DB／NGINX 共 21 個健康服務；HTTP suite 執行期間單次記憶體樣本合計 1,019,003,011 bytes（約 0.95 GiB），僅供本機資源紀錄，沒有量測尖峰或正式容量。六版設計未變更。原 Vue／Nuxt asset resolve warnings 仍保留；既有 dependency audit 尚未完成全面適用性分析。shellcheck、ruff、pyright 無法使用，未列為通過。跨瀏覽器、實機手機／平板、軟鍵盤、200% zoom、正式壓測及全面 CVE audit 未執行；沿用既有核准的驗證限制。以下 CQ34／PERF01 保留原十二版歷史結果。

## PERF01 查詢效能

本機提交 `3577b22` 完成十二後端的列表與搜尋量測及正式審查。使用小量和中量兩組合成資料，各執行兩輪。

- 核對 6,768 個 HTTP 請求窗口的回應、實際 SQL 及查詢次數，其中 192 個為冷機與暖機窗口。
- 比較 1,584 組每頁 1 筆和 20 筆的請求，這些案例的讀取 SQL 次數均未增加。
- 依實際發出的 SQL、綁定值與連線語境補驗 366 份小量及 396 份中量查詢計畫。小量計畫在另一個專用 PostgreSQL 環境用同分布合成資料唯讀重播。

量測工具的最終首次啟動防護以離線替身和 Compose 設定檢查驗證，實際查詢計畫另有 PostgreSQL 執行證據。這些本機樣本不設生產流量或延遲門檻。

測試入口與環境前提見[開發指南](developer-guide.md#從乾淨-checkout-可執行的離線驗收)。服務只供本機展示，未配置 GitHub Actions、公開部署或正式環境維運。
