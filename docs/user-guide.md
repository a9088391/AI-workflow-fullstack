# 使用指南

本指南以一般使用者和管理員的操作順序介紹網站。先依[本機啟動指引](database-operations.md#首次設定與日常啟停)完成首次設定，再開啟 `http://localhost:8080/`。六版前端使用相同的頁面語意和 API，外觀各有不同；以下步驟適用於六版。

## 選擇畫面與後端

網站根路徑導向 `/vue/`，第一次使用預設 Laravel API。工具列顯示目前前端與後端，可切換為下列任一組合：

| 前端 | 頁面入口 | 視覺風格 |
| --- | --- | --- |
| Vue 3 + Vite | `/vue/` | 裝幀書牆 |
| Nuxt | `/nuxt/` | 海岸玻璃 |
| React + Vite | `/react/` | 午夜放映 |
| Next.js | `/next/` | 雕塑展廳 |
| Angular | `/angular/` | 水墨長卷 |
| SvelteKit | `/sveltekit/` | 孔版海報 |

前端路徑都在 `http://localhost:8080` 下。**同一分頁切換前端**會保留目前後端、同一次登入及原到期時間，並導向對應的語意頁面；例如 Vue 的文章詳情可切到 Nuxt 的同一篇文章。此設計只承諾同一分頁，不承諾跨分頁或跨瀏覽器同步。

**切換後端**會清除目前登入，轉到登入頁；重新登入後返回合法的原目標頁面。十二後端共用資料，但各自使用獨立 JWT 金鑰；一個後端的憑證不能直接送給另一個後端。切換不搬移列表頁碼、搜尋條件、捲動位置或未提交的草稿。若畫面提示捨棄草稿，請先確認是否已保存所需內容。

以下路徑接在所選前端的入口後，例如 Vue 的「我的文章」是 `/vue/me/articles`：

| 路徑 | 用途 |
| --- | --- |
| `/`、`/register`、`/login` | 公開文章、註冊、登入 |
| `/articles/:id`、`/articles/new`、`/articles/:id/edit` | 文章詳情、發表、編修 |
| `/me/articles`、`/me/comments` | 自己的文章和留言 |
| `/comments/:id`、`/comments/:id/edit` | 有權讀取的留言詳情與作者編修 |
| `/admin/...` | 管理員頁面；具體路徑見下方表格 |

## 訪客：閱讀、註冊與登入

1. 在首頁瀏覽已公開的文章；點選文章可閱讀全文和公開留言。公開作者只顯示暱稱，不顯示 Email。
2. 在「註冊」頁輸入 Email、密碼和暱稱。註冊成功後到登入頁，**不會自動登入**。
3. 登入後可建立文章、留言，並查看「我的文章」和「我的留言」。一般登入固定八小時，不因切換前端或讀取頁面而延長。

本機 demo 的密碼為 **4–16 碼 ASCII 英文字母或數字**，可只用字母、只用數字或混用；大小寫不同，不接受空白、符號或非 ASCII 字元。Email 會移除前後的 ASCII 空格並將 ASCII 大寫轉小寫，再用於比對與唯一性。暱稱為 1–30 個 Unicode 碼點，不能全是空白。

登入錯誤分別顯示帳密錯誤、帳號停用或暫時鎖定。預設鎖定設定是五分鐘內五次符合資格的錯密碼，鎖定 300 秒；管理員可改設定。若伺服器回傳鎖定剩餘秒數，登入頁會倒數並停用 Email、密碼及登入按鈕；歸零後恢復操作，但**不會自動登入**。重新整理畫面不會解除伺服器鎖定。

## 會員：文章與留言

| 工作 | 操作與結果 |
| --- | --- |
| 發表文章 | 登入後選「發文」，輸入純文字標題與內文。發表即公開；成功後回「我的文章」第一頁。 |
| 留言 | 在公開文章詳情送出純文字留言；成功後留在該文章並重讀留言。文章已下架時不能新增留言。 |
| 編修 | 只可修改自己的文章或留言內文；管理員也不能改寫他人的內文。送出前使用畫面讀到的版本，若其他操作已更新，會要求重讀。 |
| 下架／恢復 | 作者可下架自己的內容，並恢復自己控制的下架內容。管理員也可下架；其下架或接管的內容須由有權的管理員恢復。 |
| 我的內容 | 「我的文章」及「我的留言」會包含自己已下架的內容；父文章下架時，留言作者仍可在自己的留言頁查看有權讀取的留言。 |

標題最長 200、文章內文最長 20,000、留言最長 2,000 個 Unicode 碼點；三者都不能全是空白或含 U+0000。網站保留輸入的原文與換行，將 HTML／Markdown 當成文字。編修、下架及恢復使用版本號保護：若資料已被更新，畫面應保留輸入，讓使用者重讀後自行決定是否重試。網路中斷時，送出結果可能不明；先查詢內容是否已寫入，不要連續重按造成重複內容。


## 管理員：會員、內容與鎖定設定

首次管理員由 `ops/setup.sh` 建立。管理頁在每個前端的 `/admin/` 路徑下；API 仍使用共同的 `/api/` 路徑。

| 管理頁 | 可做的事 |
| --- | --- |
| `/admin/members` | 搜尋一般會員的 Email 或暱稱，查看會員資料、停用或恢復會員。停用會使其既有登入失效；恢復後須重新登入。 |
| `/admin/articles` | 查看含下架內容的文章列表，依權限下架或恢復。 |
| `/admin/comments` | 查看含個別下架及父文章下架的留言，依權限下架或恢復。 |
| `/admin/settings/login-lockout` | 讀取與更新共用登入鎖定設定；改動會影響全部十二個後端。 |

管理員不能將會員從畫面升級為管理員，也不能透過管理頁修改他人的文章或留言內文。登入鎖定設定必須一次送出啟用狀態、計數視窗、失敗門檻及鎖定秒數四欄；關閉鎖定會清除現有計數與鎖定，重新開啟使用保存的數值。

## 看見錯誤或空白列表時

- 「尚無資料」、「沒有符合的搜尋結果」與「這一頁沒有資料」是不同狀態。超過最後一頁時可回第一頁；頁碼與總筆數仍以 API 回傳值為準。
- `401` 通常表示登入缺少、過期、已撤銷或切換了後端；重新登入後再操作。`403` 表示目前身分無權操作，或帳號已停用。`404` 也可能表示隱藏內容對目前身分不可讀。
- `409` 表示內容版本已變；先讀取最新內容，確認自己的修改後再手動送出。`422` 是輸入欄位不符合規則。`429` 是暫時鎖定。
- API 或網路暫時失敗時，頁面應提供錯誤及手動重試，不能將失敗當成真正的空列表。若錯誤有 `log_id`，回報問題時一併提供，勿提供密碼或 JWT。

需要查詢每個操作的確切欄位與錯誤格式時，參閱[會員文章 API](article-api.md)。
